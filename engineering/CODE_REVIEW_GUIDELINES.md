# Code Review Guidelines

## Purpose

This document defines the principles and expectations for reviewing code across all software projects within this technology foundation.

Code review is a quality improvement process, not a fault-finding process.

---

# Review Objectives

Every review should improve:

- Code quality
- Security
- Reliability
- Maintainability
- Knowledge sharing

---

# Review Principles

Reviews should be:

- Respectful
- Constructive
- Objective
- Evidence-based
- Consistent

Focus on improving the software, not criticizing the developer.

---

# What to Review

Reviewers should verify:

- Correctness
- Readability
- Maintainability
- Architecture alignment
- Security considerations
- Error handling
- Documentation updates
- Test coverage

---

# Code Quality

Ensure the code:

- Has a clear purpose
- Follows coding standards
- Avoids unnecessary complexity
- Uses meaningful names
- Minimizes duplication

---

# Security Review

Verify:

- Input validation
- Access control
- Secure data handling
- Safe error handling
- No sensitive information is exposed

Security should always be reviewed.

---

# Documentation Review

Confirm that:

- Technical documentation is updated
- New behavior is explained
- Important decisions are recorded

Code and documentation should remain synchronized.

---

# Testing Review

Verify that:

- New functionality is tested
- Existing functionality is not broken
- Critical scenarios are covered

Testing supports release confidence.

---

# Review Outcome

Every review should end with one of the following:

- Approved
- Approved with minor improvements
- Changes requested

The objective is quality, not speed.

---

# Final Principle

Every review is an opportunity to improve the product, strengthen engineering practices, and share knowledge across the team.
